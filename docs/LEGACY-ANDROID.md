# 제우스 보스 타이머 0.2.1

> 아래 내용은 기존 Android 앱의 사양과 초기 기록입니다. 새 작업은 Android·iPhone 공통 PWA로 전환합니다. 최신 요구사항은 [ROADMAP.md](ROADMAP.md), 보존한 관측값과 최신 스크린샷 기준 시각은 [BOSS-OBSERVATIONS.md](BOSS-OBSERVATIONS.md)를 따릅니다. 새 웹앱은 아직 구현되지 않았습니다.

안드로이드 8.0 이상 개인용 앱. 인터넷 연결이나 게임 API 없이 수동으로 입력한 게임 카운트다운을 사용합니다. 게임과 연동되거나 게임 화면을 자동 인식하는 앱은 아닙니다.

## 첫 화면 목록과 보스 정보

첫 화면은 레벨이 낮은 순서의 간결한 리스트입니다. 시간이 지났거나 남은 시간을 보정해도 레벨 정렬을 유지합니다. 행을 누르면 시간 입력, 우측 `⋮`를 누르면 기록 보기·목록에서 빼기를 사용할 수 있습니다.

- **+ 보스 추가:** 코드에 등록된 보스 중 현재 숨긴 보스를 선택해 다시 표시합니다.
- **목록에서 빼기:** 첫 화면에서 숨기고 해당 보스의 예약 알림을 끕니다. 관측 기록·예정 시각은 보관합니다.
- **첫 화면 목록 관리:** 여러 보스의 표시 여부를 한 번에 변경합니다.
- **알림 체크:** 표시 여부와 별도입니다. 다시 추가해도 알림은 자동으로 켜지지 않습니다.

보스의 이름·레벨·지역·리스폰 정보는 `app/src/main/java/kr/local/zeustimer/BossCatalog.java`에서 수정합니다. 앱에는 게임 정보 직접 작성 폼이 없습니다. 예:

```java
new Definition("stable-id", "보스 이름", 70, "지역", 12)
```

순서대로 고정 ID, 이름, 레벨, 지역, 처치 후 리스폰 시간(시)입니다. **ID는 업데이트 때도 그대로 유지**해야 기존 출현 기록과 연결됩니다. 새 항목은 설치된 앱의 업데이트 후 추가 목록에 나타나며 첫 화면에는 자동으로 넣지 않습니다. 기존 보스의 메타데이터만 코드 값으로 갱신하고 사용자의 표시·알림 선택과 출현 기록은 유지합니다. 코드에서 뺀 항목의 기존 개인 기록도 강제 삭제하지 않습니다.

0.1.0에서 업데이트하면 기존 기록과 알림 선택을 보존하고 레벨을 채웁니다. 이전 버전에서 삭제했던 보스는 숨김 상태로 복구되어 추가 목록에서 다시 선택할 수 있습니다.

## 설치와 첫 사용

1. `zeus-boss-timer.apk`를 휴대폰으로 옮기고 파일 앱에서 열어 설치합니다. 설치에 사용한 파일 앱의 ‘알 수 없는 앱 설치’ 허용이 필요할 수 있습니다.
2. 앱의 **알림 설정**에서 알림, 정확한 알람을 허용합니다. **진동 채널 설정**에서 진동이 켜져 있는지 확인합니다.
3. **5초 뒤 진동 테스트**를 누르고 화면을 잠가 실제 알림을 확인합니다. 기본 알림은 소리 없이 진동과 알림창입니다.
4. 목록에서 원하는 보스의 **알림** 체크박스를 켭니다. 기본은 모두 꺼져 있습니다. 체크하지 않은 보스는 출현 알림을 예약하지 않습니다.
5. 기본 알림은 출현 5분 전과 예정 시각입니다. 설정에서 10분·5분·1분 전과 예정 시각을 선택할 수 있습니다. 숨긴 보스는 알림 대상에서 제외됩니다.

알림은 서버에서 보내는 원격 푸시가 아니라 폰에 예약하는 로컬 알림입니다. 앱 화면을 닫아도 시스템이 알림을 처리합니다. 재부팅 시 미래 알림을 복구합니다. 강제 종료 뒤에는 앱을 다시 열어야 합니다. 방해 금지·기기 알림 설정이 진동을 막을 수 있으므로 실제 폰에서 잠금 화면과 절전 상태를 확인하세요. 정확한 알람 권한이 없으면 지연될 수 있습니다.

## 남은 시간 보정

- **남은 시간 입력**을 누르는 순간을 관측 시각으로 잡습니다. 스크린샷을 나중에 입력한다면 실제 촬영 시각으로 고칩니다. 모든 입력·표시는 한국시간입니다.
- 시·분·초를 입력합니다. 게임이 분까지만 보여 준다면 초는 비워 둡니다.
- 같은 회차 카운트다운은 **다음 회차 기록**을 해제한 채 보정합니다. 보정은 같은 회차의 기록을 교체하며 새 학습 표본으로 세지 않습니다.
- 이전 보스 출현 뒤 새 카운트다운이 생겼다면 **다음 회차 기록**을 체크합니다.
- 중간 회차를 놓쳤다면 **중간 출현을 놓쳤음**을 체크해 긴 간격을 학습에서 제외합니다.
- 미리보기에서 계산한 시각을 확인하고 저장하면 기존 알림을 취소하고 선택된 보스의 미래 알림만 다시 예약합니다. 이미 지난 알림은 몰아서 울리지 않습니다.

`이번 출현 시각 = 관측 시각 + 남은 시간`

`역산 처치 시각 = 이번 출현 시각 − 직접 설정한 리스폰 주기`

`이전 생존 시간 = 이번 출현 시각 − 이전 출현 시각 − 리스폰 주기`

처치 역산과 생존 시간은 ‘처치 후 고정 주기로 다시 출현’하는 구조를 가정합니다. 점검·이벤트·서버 초기화·소멸 등의 예외에는 새 카운트다운으로 보정하세요.

서로 다른 회차가 두 개 이상 쌓이면 최근 최대 10개의 유효한 출현 간격 중앙값으로 다음 회차를 추정합니다. 리스폰 주기보다 짧은 간격과 놓친 회차의 간격은 제외합니다. 화면의 범위는 관측된 편차와 입력 정밀도로 계산한 참고 범위이며 확률적 신뢰구간이 아닙니다. 한 개 간격만 있을 때는 ‘자료 부족’으로 표시합니다.

이번 회차의 예정 시각이 지난 뒤 **기록 · 설정 → 다음 예상으로 알림 예약**을 선택할 수 있습니다. 추정은 실제 관측으로 학습시키지 않으며, 추정 시각이 지나도 계속 자동 반복하지 않습니다. 게임에서 새 시간을 확인하면 새 회차로 기록하세요.

## 기록 보관

보스·회차·알림 선택을 기기에 저장합니다. **기록 내보내기**로 JSON 백업을 저장하고 **기록 가져오기**로 복원할 수 있습니다. 가져오기는 현재 보스 기록을 교체하며 기존 알림을 취소한 후 새 기록의 선택 상태에 맞춰 예약합니다. 삭제·앱 데이터 초기화·제거 전에 내보내세요. 앱의 인터넷 권한은 업데이트 조회·다운로드에만 사용합니다. 게임 계정·화면 캡처 권한은 사용하지 않습니다.

## GitHub 업데이트

업데이트 저장소는 [mucheol/zeus-bossTimer](https://github.com/mucheol/zeus-bossTimer)입니다. 0.2.1부터 이 저장소의 최신 릴리스를 조회합니다. 저장소 주소가 비어 있는 이전 APK는 연결된 새 APK를 한 번 직접 설치해야 합니다.

공개 GitHub Releases에 `latest.json`과 `zeus-boss-timer.apk`를 올리는 방식입니다. 앱 실행 시 최대 하루에 한 번 조회하며 **새 버전 확인** 버튼으로 즉시 조회할 수도 있습니다. 새 버전이 있으면 다운로드 버튼을 제공합니다. APK의 SHA-256, 앱 ID, 더 높은 버전 코드, 기존 앱과 같은 서명인지 확인한 후 안드로이드 설치 화면을 엽니다. 설치에는 ‘이 앱에서 알 수 없는 앱 설치’ 허용과 시스템 설치 확인이 필요할 수 있습니다. 무조건 무인 설치를 보장하는 방식은 아닙니다.

비공개 저장소는 익명으로 릴리스 파일을 받을 수 없으므로 별도의 공개 업데이트 저장소나 인증 서버가 필요합니다. APK에 GitHub 토큰을 넣지 마세요. 보스 기록은 GitHub에 업로드하지 않습니다. 친구들 각자의 기록과 체크 상태는 각자 폰에 저장되며 공유 동기화는 구현하지 않았습니다.

`tools/release-info.ps1`로 APK 해시를 포함한 배포 정보를 생성합니다.

```powershell
.\tools\release-info.ps1 -Repository 'owner/repo' -ApkPath 'C:\build\zeus-boss-timer.apk'
```

`release-workflow.yml.example`은 main 브랜치에 코드가 올라올 때 테스트·서명 빌드·릴리스 생성을 자동화하는 준비 파일입니다. 저장소 루트에 이 프로젝트를 올리고 `.github/workflows/release.yml`로 배치한 뒤 GitHub Actions Secrets에 `ZEUS_KEYSTORE_BASE64`, `ZEUS_KEYSTORE_PASSWORD`를 설정해야 합니다. 첫 배포 APK와 **동일한** 키스토어를 사용하세요. GitHub에서 워크플로를 실제 실행하거나 파일을 게시하지는 않았습니다. 예제의 기본 브랜치는 main이며 환경에 맞게 바꿀 수 있습니다.

## 빌드

외부 앱 라이브러리 없이 Android SDK, JDK 17, Node.js로 빌드합니다. 제공된 `build.ps1`은 리소스 패키징, Java 컴파일, 계산 테스트, D8, APK 서명과 정렬 검증을 수행합니다. 이 PC에서 AAPT가 ZIP 마감 중 비정상 종료하는 문제가 있어, 완전히 기록된 로컬 엔트리의 압축 해제·크기·CRC를 모두 검사한 후 Node.js로 ZIP 디렉터리를 재구성합니다. 서명 검증과 공식 zipalign·aapt 읽기 검증까지 통과한 경우에만 완료됩니다.

```powershell
.\build.ps1 -JdkPath 'C:\tools\jdk17' `
  -BuildToolsPath 'C:\tools\android\build-tools\35.0.0' `
  -AndroidJar 'C:\tools\android\platforms\android-35\android.jar' `
  -WorkDir 'C:\work\zeus-build' `
  -Keystore 'C:\work\zeus-signing\zeus-debug.keystore'
```

빌드 전 `ZEUS_KEYSTORE_PASSWORD` 환경변수에 키스토어 암호를 설정하거나 `-KeystorePassword`로 전달하세요. 별칭 기본값은 `zeustimer`입니다. 첫 배포에 사용할 별도 서명 키를 만들었습니다. 업데이트 설치에는 같은 키스토어와 패키지명이 필요하므로 제공된 서명 키 백업은 개인적으로 보관하세요. 스토어 등록은 포함하지 않습니다. APK는 CPU 네이티브 라이브러리를 포함하지 않습니다.

## 검증 범위

시간 계산, 날짜 넘김, 같은 회차 보정, 회차 간 학습, 빠진 회차 제외, 추정을 학습시키지 않는 동작을 자동 검사합니다. 빌드와 서명 검증은 별도의 `검증결과.txt`를 참고하세요. 실물 안드로이드 기기나 에뮬레이터에서 UI와 실제 진동·절전·재부팅 알림을 검증하지는 않았습니다.
