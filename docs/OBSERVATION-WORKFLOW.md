# 새 세션의 보스 이미지 기록·적용 절차

사용자가 보스 시간표 이미지를 보내면 이 절차에 따라 원본 기록, 공통 시간 반영, 검사와 웹 배포까지 진행합니다. 단순 분석으로 끝내지 않습니다. 이 문서는 집·회사 등 어느 PC에서 작업해도 동일하게 적용합니다.

## 시작 전에 확인

1. `AGENTS.md`, `ROADMAP.md`, `BOSS-OBSERVATIONS.md`와 현재 `public/data/catalog.json`을 읽습니다. 이전 대화의 기억보다 저장소의 최신 확정 요구사항과 이번 사용자 지시를 우선합니다.
2. `git status --short`, `git remote -v`, `git fetch origin`, `git log --left-right --oneline HEAD...origin/main`으로 다른 PC의 업로드를 확인합니다. 원격은 `https://github.com/mucheol/zeus-bossTimer.git`입니다. 깨끗한 작업 트리에서 원격만 앞서면 `git pull --ff-only`로 받습니다. 로컬 변경·커밋도 있으면 보존하면서 내용을 비교·통합하고, 강제 push·reset·관측 배열 통째 덮어쓰기는 하지 않습니다.
3. 현재 배포 주소 `https://zeus-boss-timer.zeus-boss-timer.workers.dev/data/catalog.json`의 revision·최신 촬영 시각·관측도 확인합니다. 여기에는 D1 관리자 기록이 합쳐집니다. 배포에만 있는 새 이미지 기록이 발견되면 먼저 원본 출처를 확인해 로컬과 통합하고, 오래된 저장소를 바로 배포하지 않습니다. `admin-*` 기록은 D1의 원본을 유지하며 정적 파일에 중복 복사하지 않습니다.

## 이미지와 시간 읽기

- 다음 미사용 번호 `screenshot-NNN`을 정해 관측 출처 이름으로 씁니다. **이미지 파일은 저장소에 보관하지 않으며**(2026-10-14 사용자 지시) 이미지에서 읽은 시간만 기록합니다. 기존 번호를 재사용하지 않습니다. 동일 이미지·동일 관측의 재전달이면 기존 기록을 확인해 중복 추가하지 않습니다.
- 촬영 기준은 사용자가 제공한 날짜·시각, 이미지에서 확인되는 실제 촬영 시각 또는 신뢰할 수 있는 촬영 메타데이터입니다. 한국시간 `+09:00`으로 기록합니다. 업로드·다운로드·파일 복사 시각을 촬영 시각으로 간주하지 않습니다. 명백히 같은 날 이어진 자료이면 기존 기록과 사용자 설명으로 날짜를 연결할 수 있습니다. 날짜·시각이 확인되지 않으면 이미지는 보존하되 미확인 상태를 기록하고 필요한 촬영 시각만 질문합니다. 임의의 시각으로 공통 시간을 배포하지 않습니다.
- 이미지에 실제 보이는 보스 이름·레벨·지역·남은 시간만 읽습니다. 기존 보스 ID·고정 리스폰·초상화·이전 관측은 유지하고, 사진에 없다는 이유로 보스를 삭제하지 않습니다. 이름이 불명확하면 기존 원본과 대조하고 임의의 새 보스를 만들지 않습니다.
- `spawnAt`은 촬영 시각 + 표시된 남은 시간의 계산용 대표값입니다. 사진의 ‘촬영 초’와 게임의 ‘남은 초’는 별개입니다.

| 촬영 초 | 남은 초 | capturedSecondsKnown | remainingSecondsKnown | precisionSeconds |
|---|---|---|---|---|
| 확인 | 확인 | true | true | 1 |
| 확인 | 미표시 | true | false | 60 |
| 미상 | 확인 | false | true | 60 |
| 미상 | 미표시 | false | false | 120 |

촬영 초 미상 시 `:00`은 계산용 대표값이며 정확한 초가 아닙니다. 분까지만 보인 시간의 숨겨진 초를 0초로 확정하거나 실제 처치시간으로 환산하지 않습니다. ‘현재 처치시간 보정 0초’와 ‘사진의 남은 초 미상’을 혼동하지 않습니다.

## 기록과 공통 시간 반영

1. `BOSS-OBSERVATIONS.md`에 이미지 링크·원본 파일명·촬영 시각 근거·보스별 표시 시간·계산용 예정 시각·표시 정밀도·회차 판단을 추가합니다. 과거 기록과 불일치해도 과거 원본을 고쳐 맞추지 말고 새 기록에 차이와 불확실성을 남깁니다.
2. `public/data/catalog.json`의 각 보스 `observations`에 관측을 촬영 순서로 추가합니다. 예전 사진이 나중에 도착하면 촬영 순서의 올바른 위치에 넣고 기존 최신 기준을 유지합니다. 배열 마지막 항목이 해당 보스의 최신 관측이어야 합니다.
3. 같은 출현을 다시 촬영하면 기존 `cycleId`와 `consecutiveFrom`을 유지합니다. 출현·처치 후 다음 리스폰으로 바뀐 것이 확인되면 새 `cycleId`를 사용합니다. 바로 다음 회차임이 확인된 때만 `consecutiveFrom`을 연결합니다. 중간 회차가 빠졌거나 불명확하면 억지로 연속 처리하지 않습니다.
4. catalog의 `revision`은 고유하게 갱신합니다. `capturedAt`, `capturedSecondsKnown`, `source`는 실제 최신 이미지 기준을 가리키게 하고 ROADMAP의 최신 기준도 갱신합니다. D1 관리자 입력·되돌리기는 `src/catalog.js`가 촬영·저장 시각 순으로 합치므로 새 이미지보다 나중에 저장된 관리자 기준을 무시하거나 D1을 초기화하지 않습니다.
5. 처치시간 보정은 **0초로 고정**입니다(2026-10-14 사용자 지시). 지역별 기본값이나 관측 기반 학습을 넣지 않으며 `public/lib/engine.js`의 `estimate`는 항상 고정 리스폰 간격을 반환합니다. 연속 회차·정밀도는 원본 기록으로만 보존합니다.
6. 앱은 저장된 출현 절대시각과 기기 현재시각의 차이를 계산합니다. 경과 분을 누적하거나 앱 실행 시간을 기준으로 다시 시작하지 않습니다. 예정 시각이 지나면 고정 리스폰 + 유효한 보정으로 다음 회차를 계산합니다. 화면이 숨겨졌을 때 상시 타이머·조회 서비스를 추가하지 않습니다.
7. 알림·시점·침공 선택·정렬은 기기별 개인 설정입니다. 사진 반영으로 다른 이용자의 설정이나 구독을 변경하지 않습니다. 관리자 공통 시간만 전체 공유합니다.

## 검사·배포·업로드

- 관측 예정값·정밀도·이전 기록 보존·같은 회차/다음 회차를 자동 검사에 반영합니다. 과거 시점 검사 자료는 유지하며 새 이미지 때문에 오래된 테스트 시각·개수 전제가 달라지면 목적을 유지한 채 수정합니다. 관리자 시간 검사 시각은 테스트 대상 최신 이미지보다 이후여야 합니다.
- `npm test`, `npm run check`, `git diff --check`를 통과시킵니다. `npm run check`가 서비스 워커 캐시 버전을 갱신하므로 `public/sw.js` 변경도 포함합니다.
- 기존 Cloudflare 프로젝트에 `npx wrangler deploy`로 배포하고 공개 `/data/catalog.json`의 revision·최신 시각·표시 시간, 화면과 남은 분 갱신을 확인합니다. 적용 결과·검사·배포 버전은 `docs/VALIDATION.md`에 기록합니다. 로그인 등 배포가 막히면 원본·로컬 변경은 보존하고 미배포 사실과 필요한 조치만 명확히 알립니다.
- `.dev.vars`, 비밀키·관리자 비밀번호·기기 토큰·푸시 주소는 Git에 넣거나 출력하지 않습니다. 다른 PC에 배포 인증이 없으면 해당 계정으로 로그인하며 기존 VAPID 키·D1·큐·Worker를 재생성하지 않습니다. 시간·화면 수정에 APK 재빌드는 필요하지 않습니다. 네이티브 권한 등 APK 자체가 바뀔 때만 기존 서명을 유지해 업데이트 APK를 만듭니다.
- `[타입] 한글 내용`으로 커밋합니다. 원격 push는 사용자 승인 후 진행하며 현재 요청의 ‘깃에 올려줘’는 그 작업의 승인입니다. 승인 없이는 중복 추정하지 않습니다.
- push 직전 원격 주소와 브랜치를 확인하고 mucheol 인증으로 전환합니다. 원격을 다시 fetch해 다른 PC의 새 커밋이 있으면 통합·검증한 뒤 일반 push합니다. 승인된 변경만 `mucheol/zeus-bossTimer`에 올리고 강제 push는 하지 않습니다. 성공·실패와 관계없이 활성 GitHub 인증을 KimMucheol로 복원하고 원격 HEAD가 업로드한 커밋과 일치하는지 확인합니다.
